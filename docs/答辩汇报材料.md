## 一、一句话定位

本系统对标立项申报书与 `process.html` 的五层技术路线
（数据采集 → 清洗结构化 → 智能计算 → 态势分析 → 输出可视化），
实现从**多源数据采集**到**风险量化、地缘位势评估、态势研判与可视化**的完整闭环，
是一个可复现、可降级、可扩展的缅甸地缘环境智能计算原型。

## 三、核心创新点（答辩重点讲这 5 个）

1. **多源异构数据融合**：新闻文本 + GDELT 全球事件 + 夜光遥感(代理) + 宏观经济 + 人工标注历史事件，五维加权评分并做**动态权重归一化**（某维缺失时权重自动重分配，系统不崩溃）。
2. **GDELT 原始 CSV 直连通道**：绕开 DOC 2.0 API 的 IP 限流（每5秒1次），改拉每15分钟发布的原始事件文件，配**增量水位线**（只拉新批次，带宽从~35MB/轮降到~1MB），学术标准做法。
3. **事件核密度估计（KDE）**：基于 GDELT 事件经纬度做严重度加权 KDE + GADM 国界掩膜，把"风险"从省级点状升级为连续密度面，峰值精确落在仰光。
4. **地缘位势 + 空间自相关**：距离加权 1/d² 位势模型 + Moran's I 热点识别，回答"哪些省份地缘上最重要、风险是否空间聚集"。
5. **工程健壮性**：数据源健康监控（近期窗口判定 healthy/degraded/dead）+ 全链路优雅降级 + 数据外置(DATA_ROOT) + 密钥隔离(.env) + 线程安全单例 + XSS 防护。

## 八、答辩高频问答预演（Q&A）

**Q1 系统与一般新闻爬虫的区别？**
答：不止爬取，而是"采集→结构化→智能计算→态势分析→可视化"闭环；多源融合 + 地缘位势/空间自相关等空间分析，输出可解释的风险研判而非简单聚合。

**Q2 风险评分如何保证客观？**
答：五维加权 + 动态权重归一化；每维数据标注可信度（官方/估算）；权重在 config.yaml 可复现；NER/情感有人工金标准验收。

**Q3 GDELT 限流怎么解决？**
答：弃用受限的 DOC API 主通道，改拉原始 CSV（不限流）+ 增量水位线只拉新批次；DOC API 降为备用。

**Q4 地图如何从"省"细化到"热点"？**
答：KDE 核密度估计，基于事件经纬度 + GADM 国界掩膜，输出连续密度面。

**Q5 系统某数据源挂了会怎样？**
答：健康监控判定 degraded/dead，自动降级（动态权重重分配），其余源照常，前端如实显示，不崩溃。

**Q6 如何复现？**
答：`pip install -r requirements.txt` + 配置 `.env` + `python app.py`；README 有完整步骤；验收环境用 Python 3.10/3.12。
