案例：观察者网《美国要挖缅甸稀土？晚了！“中国主导地位无法撼动”》（组长提供）
执行时间：2026-11-15 · 本机 venv312 · 服务 http://127.0.0.1:5000 · 模型 GLM-4-Flash
材料：`article_full.txt`（全文 4778 字）、`testset_rare_earth.json`（拆出的 10 条事件）、`analysis_results.json`（11 次解析的完整返回）、`screenshot_full_article.png`（网页实跑截图）

## 一、结论：可行，但要先说清边界

把一篇新闻拆成事件级测试集、逐条走解析链路，完全可行，本次已实跑。但「把网页各个模块都跑一遍」需要区分两类模块：

- **吃这段文本的模块**：文本分析页（实体识别 → 情感 → 风险评分 → 大模型研判 → 指标贡献分解），以及可选的链式推理。粘贴的新闻只走这条链。
- **吃已存观测库的模块**：风险地图 / KDE、趋势、关系图谱、空间统计、多源对照、遥感影像。它们读的是采集入库的正式观测，**不会**因为粘贴了一篇新闻就出现这篇新闻的事件。手工输入按设计是独立分析，不写入正式日风险、也不进共享图谱（页面上有明示）。

所以演示的正确讲法是：先用测试集展示「一条新闻如何被解析」，再切到其余模块展示「系统平时积累的观测长什么样」；若要让本文事件上地图，需要走正式入库并带来源核验，不属于手工演示路径。

## 四、演示时要主动讲清的三个局限（实测发现，非隐瞒）

1. **中文情感对这类文本失真**：SnowNLP 给全文和多数外交事件打了 ≈1.00（偏正面），情感指标因此贡献为 0。SnowNLP 训练语料偏评论体，对地缘外交 prose 不敏感；本文的风险分实际由冲突词频驱动。英文走 VADER 无此问题。这是已知后端局限，演示时建议直接说明。
2. **大模型事件类型标签偏粗**：全文被标为「经济制裁」，更贴切应是「外交/经济竞争」；摘要与影响判断仍可用。标签粒度问题，不影响流程演示。
3. **单篇手工风险分只是参考**：run_kind=manual，不进入正式日风险序列；地名识别漏了「美国/华盛顿」（词典侧重缅甸及周边），属 NER 覆盖缺口。

## 五、复现方式

- 网页：打开「分析工作台 → 文本分析」，粘贴 `article_full.txt`，点「开始分析」；勾选「启用链式推理」可加跑四步推理链。
- 脚本：`venv312\Scripts\python.exe logs\_demo_run.py`（需服务在跑），逐条事件 + 全文共 11 次调用，结果写入 `analysis_results.json`。

## 六、组长本机为什么没跑起来（诊断摘要）

1. 截图里每条 `py -3.12 …` 都报 `No suitable Python runtime found`：他机器上**没有注册到 py 启动器的 Python 3.12**（大概率根本没装 Python），所有命令在启动器阶段就失败，项目代码一行都没执行。这不是项目 bug。
2. 他的目录是 `…中期检查附件\Myanmar-Geopolitical-Risk-Analysis-Agent-main\Myanmar-Geopolitical-Risk-Analysis-Agent-main`：GitHub/附件 ZIP 解包（双层嵌套），是**旧快照**；最新改动（科技主题、遥感修复、状态灯等）还在本机工作区未提交，所以「打开了但不是最新的」。
3. 即使装好 Python，ZIP 里也没有：依赖包、`.env` 密钥、外置运行数据（DATA_ROOT）、NLTK vader 词表与 spaCy 模型——他截图里正在补的正是后两者。缺密钥时大模型降级、缺数据时各页显示缺测，均属设计内行为。

修复路径见交付沟通：装 Python 3.12 → 按 README 建 venv 装依赖 → 补两个语料 → 用最新代码包 + 离线数据包 + `.env.example` 配置；或干脆不在他本机装，直接看本演示记录与实跑截图。
