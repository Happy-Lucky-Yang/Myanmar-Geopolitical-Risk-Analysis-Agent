# 操作瘦身 Playbook（P1–P8）

每条模式：问题 → 做法 → 反例。示例取自缅甸地缘风险系统实测案例。

## P1 单主操作（One Primary Per View）
问题：一屏多个实心按钮，用户不知道先点哪个。
做法：只留核心任务为实心高对比；其余改幽灵按钮/文字链接。
案例：文本分析页原「开始分析」「填充示例」并排实心 → 「开始分析」实心，
「填充示例」改幽灵按钮；「启用链式推理」复选框移入"模型设置"折叠区。
反例：把两个业务动作合并成一个按钮（语义混淆）。

## P2 折叠 Disclosure 收纳次要操作
问题：筛选/设置控件常年展开占首屏。
做法：`<details><summary>` 默认收起，summary 上显示**当前值摘要**
（如"近30天 · 缅甸全国"），用户不展开也能知道现状。
案例：研究页筛选栏默认收起 + summary 摘要行；展开后才见 days/region/source。
反例：折叠后 summary 无摘要，用户被迫展开确认 = 更累。

## P3 合并同类为分段控件/菜单
问题：3 个以上互斥选项做成 N 个按钮。
做法：互斥切换用 segmented control 或单个 `<select>`；低频批量操作进
"更多 ⋯" 菜单。
案例：地图"标准/夜光/事件密度"三按钮 → 一个图层切换分段控件。
反例：把非互斥动作塞进分段控件。

## P4 智能默认，让多数操作不必存在
问题：用户每次都要先配置才能用。
做法：给安全默认值（最近 30 天、全国、全部来源），页面加载即出结果；
配置只在用户不满足默认时才出现。
案例：dashboard 无参数直接渲染全国近 30 天；旧筛选 URL 自动 302 到明细页。
反例：默认值需要联网猜测用户意图（离线项目用静态默认）。

## P5 整卡可点，删角标重复入口
问题：卡片右上角"明细 →"链接 + 卡片本身都可点 = 两个操作位。
做法：整卡可点（含焦点态与 aria-label），角标降级为纯视觉箭头。
案例：首页四模块"查看风险明细 →"改整卡跳转，视觉箭头保留。
反例：卡内还有独立按钮时整卡可点（点击冲突）。

## P6 动词标签，删解释性按钮
问题：按钮文案是名词/长句，用户要读半天。
做法：标签 = 动词 + 对象，≤6 字（"渲染图像""导出报告"）；说明放
tooltip/帮助页，不放按钮上。
反例：按钮上写"点击此处以开始进行分析"。

## P7 空状态引导代替按钮墙
问题：首屏用一排按钮解释"能做什么"。
做法：空状态给**一个**推荐动作 + 一行说明（"粘贴一篇报道，或填充示例"）。
案例：文本分析页空态只留输入框 + 开始分析 + 示例文字链。
反例：空状态放 4 个功能入口卡片。

## P8 高级配置外移
问题：模型选择、权重、导出格式与主流程同屏。
做法：移入设置抽屉/独立页（如 /workspace、模型设置折叠区），主流程
只显示**当前生效值**一行只读文本。
案例：风险解读页模型选择收进"模型设置" summary；主区只显示"当前：DeepSeek-chat"。
反例：外移后主流程完全不显示生效值（用户失去掌控感）。

## 验收清单

- [ ] 每屏实心主按钮 = 1
- [ ] 首屏可见操作 ≤ 7±2（count_actions.py 复测）
- [ ] 被收纳操作 ≤ 2 次点击可达
- [ ] 折叠 summary 带当前值摘要
- [ ] 无同一动作的重复入口
- [ ] 浏览器契约测试全绿
