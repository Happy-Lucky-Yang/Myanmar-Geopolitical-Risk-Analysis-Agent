# 界面操作瘦身（Action Diet）

老师/评审说"按钮太多、晕"，根因通常不是数量，而是**操作平权**：主操作、
次要操作、高级配置以同等视觉权重摊在同一屏。本技能用四步把界面瘦到
"一眼知道点哪"。

## 预算规则（硬指标）

- 每屏**主操作恰好 1 个**（唯一高对比实心按钮）。
- 首屏可见操作 **≤ 7±2**（按钮+按钮化链接+下拉+输入合计）。
- 次要操作默认**折叠**（`<details>/<summary>` 或"更多"菜单），折叠态只占 1 个操作位。
- 高级配置（模型、参数、导出格式）**移去独立页/设置抽屉**，不在主流程露出。
- 同一动作**只留一个入口**：导航、卡片角标、页内按钮三处重复 = 删两处。
- 导航链接不计入操作预算，但一级导航 ≤ 6 组。

## 工作流

### Step 1 盘点计数

```bash
python scripts/count_actions.py <模板目录或html文件...> [-o report.md]
```

零依赖（标准库 html.parser），自动排除 `display:none` / `hidden` /
`type=hidden` / `<template>` 内容；导航链接与折叠单独列列示。
Jinja 模板可直接解析；若要精确到"首屏折叠线以上"，用 Playwright 打开
页面按 `getBoundingClientRect().top < 900` 复算（可选，非必需）。

### Step 2 给每个操作分级

对超标页面逐控件标注：

| 级别 | 判定 | 处置 |
|------|------|------|
| P 主操作 | 本页核心任务（分析/保存/提交） | 保留，唯一实心高对比 |
| S 次要 | 辅助主任务（示例填充、上传、刷新） | 折叠或降级为文字链接 |
| A 高级 | 专家配置（模型、权重、导出格式） | 移设置抽屉/独立页 |
| R 冗余 | 与他处重复的入口 | 删除，留信息层级最高处 |
| D 死操作 | 无消费点/永远禁用 | 直接删除 |

### Step 3 按 playbook 瘦身

逐条套用 `references/reduction-playbook.md` 的模式 P1–P8
（单主操作、折叠 Disclosure、合并分段控件、智能默认、整卡可点、
动词标签、空状态引导、设置外移）。改完同步更新依赖 DOM 的测试选择器。

### Step 4 复审计与报告

重跑 Step 1 对比前后合计；输出 Markdown 表（页 × 前后数量 × 采用的模式），
需要可视化对比时用 `/canvas` 出前后对照报告。向用户汇报时先给结论：
"首屏操作从 N 降到 M，主操作 1 个"。

## 注意

- 瘦身不等于删功能：被折叠/外移的操作必须仍可达（≤2 次点击）。
- 保留无障碍：折叠用原生 `<details>` 或带 `aria-expanded` 的按钮。
- 有浏览器契约测试的项目，改导航/按钮结构后立刻跑相关测试再收工。
