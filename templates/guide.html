How It Works

系统如何工作

数据采集 → 清洗与实体识别 → 风险及空间计算 → 证据解读 → 可视化与报告。每个页面回答什么、不能证明什么，都写在这里。

  1. 采集新闻、GDELT 事件与外部观测
  2. 结构化去重、实体识别、发生地定位
  3. 计算风险评分、位势、空间统计、网络
  4. 解读贡献拆解与有证据的 AI 研判
  5. 呈现地图、趋势、图谱与报告

先读懂筛选条件

区域代码 MMR
MMR 是缅甸的三字母国家代码，表示全国。省邦代码取自 GADM 边界；选某省表示事件发生地子集，不是把全国风险分套给该省。
来源
留空为全部来源，选项来自实际保存的新闻。单一来源不提供全国综合评分，不能把部分证据当作全量。
截止业务日与时间窗口
按 Asia/Yangon 时区，包括截止日的连续日历。未观测日为空，不会自动复制上一日数值。
数据域
observed：正式采集资料衍生的观测系列；legacy：旧口径历史，只供对照；demo：演示数据，不是事实。observed 不表示算法结论已经人工验证。
运行方式
live 表示本次采集，existing 表示分析本地已有资料，manual 表示用户手工输入。运行方式不等同于数据域；手工文本不更新全国日风险。

技术架构与当前困难

前端使用 Jinja2、原生 JavaScript、ECharts 和 Folium/Leaflet；后端使用 Flask 与 Python 分析模块。多人账户和任务复用 PostgreSQL、独立 worker 与 Alembic；Neo4j 是可选能力。

亮点是版本和证据可追踪、缺测不伪造、图谱与风险不重复计量、引用有出处、个人对话隔离。真实 ACLED/OFAC/VIIRS/IDMC 接入、九指标正式链路、NER独立留出验收与云端多人联调仍有待完成。

满意度用于改进产品体验，不等于模型训练或事实准确率。文献中心提供题录/摘要与合法外部入口，不公开团队私密 PDF。
